# first-pr-practice

A practice repository for learning the GitHub pull request (PR) workflow.

## What is this?

This repo exists to walk through changing code the way real projects do —
not by editing `main` directly, but by proposing changes for review:

1. **Branch** — create a branch off `main` for your change
2. **Commit** — make the change and save it with a message
3. **Push** — upload the branch to GitHub
4. **Pull request** — open a PR proposing your branch be merged into `main`
5. **Review & merge** — discuss, approve, and merge it in

## Why branches and PRs?

Keeping changes on their own branch means `main` always stays working,
and every change gets a chance to be reviewed before it lands.
